## Plugin Contract

A plugin must implement:

```python
execute() -> PluginResult
```

Example:

```python
from lib.models.plugin import PluginResult
from lib.plugins.base import BasePlugin

from .exceptions import CacheRefreshPluginException


class CacheRefreshPlugin(
    BasePlugin,
):
    def execute(
        self,
    ) -> PluginResult:

        self.message.info(
            "Starting cache_refresh.",
        )

        with self.activity(
            "cache_refresh",
        ):

            self._execute()

        self.message.success(
            "cache_refresh completed successfully.",
        )

        return PluginResult(
            success=True,
            changed=True,
            outputs=dict(
                self.outputs,
            ),
            metadata={
                "artifacts": {
                    name: str(path)
                    for name, path in self.artifacts.items()
                },
            },
        )
```

A `PluginResult` contains:

| Field | Description |
|-------|-------------|
| `success` | Whether the plugin operation succeeded. |
| `changed` | Whether the plugin changed external state. |
| `outputs` | Structured values available to later workflow steps. |
| `changes` | Structured information about changes performed. |
| `errors` | Structured operation errors. |
| `warnings` | Non-fatal warnings. |
| `metadata` | Additional execution metadata. |

## Plugin Exceptions

Plugin-specific exceptions belong in:

```text
exceptions.py
```

The generated exception class inherits from `PluginException`:

```python
from lib.plugins.exceptions import PluginException


class CacheRefreshPluginException(
    PluginException,
):
    """
    Base exception for the cache_refresh plugin.
    """
```

Raise the plugin-specific exception when the plugin encounters an invalid plugin-specific condition:

```python
raise CacheRefreshPluginException(
    "Source directory does not exist.",
)
```

Do not print the same exception through `message.error()` and then raise it.

The Entropy runtime is responsible for rendering execution errors.

## Development Guidelines

- Keep `execute()` focused on orchestration.
- Put implementation details in plugin-owned modules or private methods.
- Return a `PluginResult` from every successful plugin execution.
- Use `success=False` with structured `errors` for controlled plugin-operation failures where appropriate.
- Raise `PluginException` or a plugin-specific subclass for invalid plugin conditions and runtime failures.
- Do not duplicate exception rendering with `message.error()` followed by `raise`.
- Use `self.activity()` for operations that should appear as an execution activity.
- Use `self.message.debug()`, `info()`, `success()`, and `warning()` for runtime messages.
- Use `self.ui` for rich interactive output when appropriate.
- Store workflow-consumable values in `self.outputs`.
- Register generated files in `self.artifacts`.
- Keep plugin-specific implementation code inside the plugin package.
- Keep the public plugin entry point in `plugin.py`.
- Keep plugin-specific exceptions in `exceptions.py`.
